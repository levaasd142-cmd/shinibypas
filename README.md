## Что это

TheMarket состоит из двух процессов, которые работают с одной базой SQLite: **Telegram-бот** (витрина для покупателей) и **панель управления** (сайт для владельца и сотрудников). Бот показывает каталог, принимает оплату и выдаёт товар. В панели вы ведёте каталог и склад, обрабатываете ручные заказы, отвечаете покупателям, смотрите платежи, аналитику и журнал.

Возможности:

- **Два режима выдачи**: автоматически из загруженного стока (ключи, аккаунты, коды) или через менеджера (услуги).
- **Оплата**: Telegram Stars, внутренний баланс магазина и USDT в сетях BEP20 (BSC), TON, TRC20 (TRON) и Aptos — с проверкой перевода в блокчейне по TXID.
- **Кошелёк покупателя**: пополнение Stars или USDT, оплата покупок с баланса, история операций.
- **Покупка нескольких единиц** (1–100), резерв стока на время оплаты, повторное получение купленного, кнопка **«🔁 Купить снова»**.
- **Витрина**: фото товара, бейдж («Хит», «Новинка»), старая цена зачёркнутой, порядок товаров внутри категории.
- **Промокоды на баланс**: код зачисляет фиксированную сумму в кошелёк покупателя; лимиты активаций (всего и на покупателя), сроки, защита от подбора.
- **Чат поддержки**: покупатель пишет в боте, сотрудник отвечает из панели, ответ приходит в тот же чат.
- **Сотрудники с ролями** (владелец, менеджер, поддержка): у каждого свой логин, вход через страницу входа, журнал показывает, кто что сделал.
- **Уведомления сотрудникам** в Telegram: оплаченные заказы, данные по ручным заказам, сообщения в поддержку, малый остаток, проблемные платежи, ошибки, ежедневная сводка.
- **Двуязычный бот** (русский/английский), фирменные баннеры, кастомные эмодзи Telegram.
- **Рассылки** с выбором аудитории (сегменты) и отложенным запуском; автоматические анонсы новых товаров и пополнения стока.
- **Обязательная подписка на канал** при первом входе (по желанию).
- **Панель**: обзор-дашборд, быстрый поиск и переходы по **Ctrl+K**, светлая и тёмная тема.
- **Аналитика**: выручка, себестоимость, расходы, возвраты, прибыль; экспорт в Excel и CSV.
- **Журнал действий и ошибок**, отдельный список проблемных платежей.
- **Зашифрованные резервные копии** с автоматической проверкой восстановления.
- **Окно запуска для Windows** — магазин запускается двойным щелчком, без терминала.
- **Рассчитан на тысячи покупателей** и сотни тысяч заказов (см. «Производительность и масштаб»).

## Быстрый старт (Windows)

**Что нужно:** Python **3.12 или новее** с [python.org](https://www.python.org/downloads/). В установщике оставьте включёнными **tcl/tk** (нужен для окна запуска) и **py launcher**. Ярлык `python` из Microsoft Store не подходит — START.cmd его пропускает.

1. Распакуйте магазин в отдельную папку.
2. Дважды щёлкните **`START.cmd`** (или запустите `start.ps1` в PowerShell). Скрипт найдёт подходящий Python и откроет окно запуска.
3. При первом запуске окно само создаст окружение `.venv`, установит библиотеки и файл `.env` с паролем панели и ключом шифрования. Это занимает несколько минут; ход видно в «Журнале запуска». Если подготовка не удалась, появится кнопка **«↻ Повторить подготовку»**.
4. Заполните три поля: **токен бота** (от @BotFather), **контакт поддержки** и **условия покупки**.
5. Нажмите **«▶ Запустить всё»** — запустятся панель и бот, панель откроется в браузере. **«Только панель»** запускает панель без бота (удобно, чтобы сначала заполнить каталог).
6. Логин и пароль панели — кнопка **«Логин и пароль»** (логин по умолчанию `owner`). Это учётная запись **владельца**; сотрудникам заведите свои в разделе «Сотрудники».

Полезно знать:

- **Закрытие окна останавливает магазин.** Бот и панель завершаются аккуратно, данные сохраняются. Если окно запуска аварийно закрылось, дочерние процессы тоже останавливаются сами.
- Панель слушает только `127.0.0.1`. Если порт 8080 занят, окно выберет следующий свободный (до +20) и покажет адрес.
- Второе окно запуска для той же папки не откроется — появится сообщение, что экземпляр уже работает.
- **«Открыть папку»** открывает папку магазина: там лежат `.env` и `data/` (база, копии, логи).

Окно запуска (`launcher.py`) работает и на Linux/macOS, если у Python есть модуль `tkinter`: `python3 launcher.py`.

## Быстрый старт (Linux/macOS, вручную)

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run.py init      # создаёт .env (пароль панели, STOCK_KEY), существующий не трогает
.venv/bin/python run.py panel     # панель: http://127.0.0.1:8080
```

Откройте панель — появится страница входа. Логин — `ADMIN_USER` (`owner`), пароль — значение `ADMIN_PASSWORD` в `.env`; это владелец магазина.

Заполните в `.env` `BOT_TOKEN`, `SUPPORT_CONTACT` и `SHOP_TERMS`, затем во втором терминале:

```bash
.venv/bin/python run.py bot
```

Все команды `run.py`:

| Команда | Что делает |
|---|---|
| `run.py init` | Создаёт `.env`, если его нет. Если есть — сохраняет его и только дописывает недостающие `ADMIN_USER`/`ADMIN_PASSWORD` (пароль короче 16 символов заменяется новым). `STOCK_KEY` никогда не меняется. |
| `run.py panel` | Запускает панель (команда по умолчанию). |
| `run.py bot` | Запускает Telegram-бота. |
| `run.py demo` | Добавляет три **скрытых** демо-товара, если каталог пуст. Сток и заказы не создаются. |
| `run.py backup create` | Создаёт и проверяет резервную копию. |
| `run.py backup verify <архив> --key <ключ>` | Полностью проверяет архив. |
| `run.py backup restore <архив> --key <ключ> --output <новая папка>` | Восстанавливает архив в новую папку. |

На Windows вместо `.venv/bin/python` используйте `.\.venv\Scripts\python.exe`.

## Docker

В комплекте `Dockerfile` (python:3.13-slim, зависимости строго по `requirements.lock`) и `compose.yaml` с двумя сервисами на одном образе:

| Сервис | Команда | Профиль | Порт |
|---|---|---|---|
| `panel` | `python run.py panel` | — (всегда) | `127.0.0.1:8080` на хосте |
| `bot` | `python run.py bot` | `telegram` | нет |

### Первый запуск

1. Создайте `.env` на хосте. Проще всего — `python3 run.py init` (для этой команды достаточно `pip install cryptography`).
   Особенности формата для Compose: значения **без кавычек**; символ `$` Compose считает подстановкой переменной — избегайте его в паролях и токенах (или пишите `$$`, но тогда такой `.env` не подойдёт для запуска без Docker).
2. Только панель:
   ```bash
   docker compose up -d --build
   ```
3. Когда в `.env` заполнены `BOT_TOKEN`, `SUPPORT_CONTACT`, `SHOP_TERMS` — панель и бот:
   ```bash
   docker compose --profile telegram up -d --build
   ```

### Тома, здоровье, остановка

- Все данные — в именованном томе `shop-data` → `/app/data`: база, резервные копии, ключ восстановления, логи. Код в образе принадлежит root и доступен приложению только на чтение; писать можно только в `/app/data`.
- **Healthcheck**: панель — `GET /healthz` (без авторизации, отвечает `{"ok": true}`); бот — процесс жив и база читается.
- `init: true` и `stop_grace_period: 30s`: при `docker compose stop` бот и панель успевают завершить доставку и закрыть базу.
- Логи контейнеров ограничены (json-file, 3 × 10 МБ); дополнительно пишутся файлы в `/app/data/logs`.
- `DATABASE_PATH`, `HOST`, `PORT` и `FORWARDED_ALLOW_IPS` заданы в `compose.yaml` в блоке `environment` и **перекрывают** значения из `.env`. Меняйте их в `compose.yaml` (или в `compose.override.yaml`).

### Доступ к панели извне: HTTPS-прокси

Вход в панель — по логину и паролю с сессионной cookie, поэтому **открывать её извне можно только через HTTPS** (за HTTPS-прокси cookie получает флаг `Secure` по заголовку `X-Forwarded-Proto`). Порт опубликован лишь на `127.0.0.1` хоста; снаружи ставьте reverse proxy с TLS. Пример для nginx:

```nginx
server {
    listen 443 ssl http2;
    server_name shop.example.com;

    ssl_certificate     /etc/letsencrypt/live/shop.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/shop.example.com/privkey.pem;

    client_max_body_size 8m;              # сток — до 6 МБ, фото товара — до 5 МБ

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host              $host;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Что важно настроить:

- **`proxy_set_header Host $host`** — панель сверяет заголовок `Origin` с `Host` для всех изменяющих запросов. Без него сохранение в панели будет отклоняться.
- **`PANEL_ORIGIN`** (в `.env`) — если прокси не может передать исходный `Host`, укажите публичный адрес панели явно: `PANEL_ORIGIN=https://shop.example.com` (можно несколько через запятую).
- **`FORWARDED_ALLOW_IPS`** — uvicorn доверяет `X-Forwarded-For`/`-Proto` только от этих адресов. По умолчанию `127.0.0.1`. В Docker запросы от прокси на хосте приходят с адреса шлюза docker-сети (например, `172.18.0.1`) — впишите его в `compose.yaml`. Это нужно, чтобы блокировка подбора пароля считала попытки по реальному IP клиента. Никогда не ставьте `*`, если порт панели доступен кому-то ещё.

### Обновление

```bash
docker compose exec panel python run.py backup create     # сначала копия
git pull                                                  # или распакуйте новую версию
docker compose --profile telegram up -d --build
```

Миграции базы выполняются автоматически при старте. После обновления обновите страницу панели с **Ctrl+F5**.

## Настройки (.env)

`.env` лежит в папке магазина. Переменные окружения процесса имеют приоритет над `.env`. После изменения перезапустите панель и бота.

| Переменная | По умолчанию | Описание | Секрет |
|---|---|---|---|
| `ADMIN_USER` | `owner` | Логин **владельца** панели (3–32 латинские буквы, цифры, `_ . -`). | |
| `ADMIN_PASSWORD` | создаётся `init` | Пароль владельца, **не короче 16 символов**. Обязателен для панели. Этот пароль всегда подходит для входа владельца `ADMIN_USER`. | **да** |
| `PANEL_BASIC_AUTH` | — | `1` — дополнительно принимать HTTP Basic Auth (`ADMIN_USER`/`ADMIN_PASSWORD`, права владельца) для скриптов. Иначе вход только через страницу входа. | |
| `STOCK_KEY` | создаётся `init` | Ключ Fernet, которым шифруются сток и другие данные. Обязателен для панели и бота. **Никогда не меняйте у существующей базы.** | **да** |
| `DATABASE_PATH` | `data/shop.sqlite3` | Путь к базе. Относительный путь — от папки магазина. | |
| `STARS_PER_USD` | `100` (пишет `init`) | Курс Stars за $1 для **первого** перевода магазина в доллары (см. «Деньги и учёт»). Дальше курс меняется в панели. | |
| `SHOP_NAME` | `TheMarket` | Название магазина в сообщениях бота. | |
| `BOT_TOKEN` | — | Токен бота от @BotFather. Обязателен для бота. | **да** |
| `SUPPORT_CONTACT` | — | Текст раздела «Поддержка» (например, `@support`). Обязателен для бота. | |
| `SHOP_TERMS` | — | Условия покупки, выполнения и возврата. Обязателен для бота. | |
| `ADMIN_CHAT_ID` | — | Ваш числовой Telegram ID: команда `/emoji` и список чатов для уведомлений **по умолчанию** (можно несколько через запятую). После сохранения раздела «Уведомления» в панели действует список из панели. | |
| `HOST` | `127.0.0.1` | Адрес панели. В Docker — `0.0.0.0` (задан в `compose.yaml`). | |
| `PORT` | `8080` | Порт панели. | |
| `PANEL_ORIGIN` | — | Публичный адрес панели за прокси, например `https://shop.example.com`; несколько — через запятую. | |
| `FORWARDED_ALLOW_IPS` | `127.0.0.1` | Адреса прокси, которым uvicorn доверяет заголовки `X-Forwarded-*`. | |
| `BSC_WALLET` | — | Адрес получения USDT BEP20, пока в панели не сохранён свой. | |
| `BSC_RPC_URL` | `https://bsc-dataseed.bnbchain.org` | JSON-RPC узел BNB Smart Chain, только HTTPS. | |
| `BSC_CONFIRMATIONS` | `20` | Требуемые подтверждения BEP20; меньше 20 не бывает. | |
| `BACKUP_DIRECTORY` | `<папка базы>/backups` | Папка резервных копий. | |
| `BACKUP_RECOVERY_KEY_PATH` | `<папка базы>/backup-recovery.key` | Файл ключа восстановления; должен быть **вне** папки копий. | |
| `BACKUP_INTERVAL_HOURS` | `24` | Интервал автокопий, 0–720 часов; `0` отключает автоматическое создание. | |
| `BACKUP_KEEP` | `14` | Сколько последних проверенных копий хранить, целое ≥ 1. | |
| `BROADCAST_RATE` | `10` | Скорость рассылок, сообщений в секунду (0.5–20). | |
| `TELEGRAM_RATE` | `25` | Общий предел исходящих сообщений бота в секунду (все ответы, выдачи, поддержка, уведомления, рассылки). Не поднимайте выше ~30 — лимит Telegram. | |
| `AUDIT_RETENTION_DAYS` | `180` | Через сколько дней удалять информационные записи журнала (заказы, товары, настройки, система). Минимум 30; `0` — не удалять. Предупреждения, ошибки и движения денег хранятся всегда. | |
| `LOG_DIRECTORY` | `<папка базы>/logs` | Папка файлов логов. | |
| `LOG_LEVEL` | `INFO` | `DEBUG`, `INFO`, `WARNING` или `ERROR`. | |

Ключи API Toncenter и TronGrid задаются не в `.env`, а в панели («Оплата и валюта»); они хранятся в базе в зашифрованном виде.

## Подключение Telegram

1. Создайте бота у **@BotFather** и скопируйте токен в `BOT_TOKEN` (или в поле окна запуска). Не отправляйте токен в чаты.
2. Заполните `SUPPORT_CONTACT` и `SHOP_TERMS` — без них бот не запустится.
3. По желанию укажите `ADMIN_CHAT_ID` (или чаты в панели, «Уведомления») и **один раз напишите боту с каждого из этих аккаунтов** — иначе Telegram не даст боту отправлять уведомления.
4. Создайте товары в панели, загрузите сток для автоматических товаров и включите «Показывать в каталоге».
5. Запустите бота и отправьте ему `/start`.

**Один процесс бота на одну базу.** Повторный запуск на том же компьютере блокируется сразу; второй экземпляр с тем же токеном на другом сервере Telegram отклонит с ошибкой конфликта. Бот сам удаляет webhook и работает через long polling.

### Способы оплаты

Включаются в панели: **«Оплата и валюта» → «Способы оплаты»**. Изменения действуют для новых счетов без перезапуска; уже выставленные счета сохраняют свои адрес и сеть и проверяются до конца, даже если способ выключить.

| Способ | Что нужно | Проверка |
|---|---|---|
| **Telegram Stars** | Ничего, включено по умолчанию. | Выдача только после `successful_payment` от Telegram. |
| **USDT BEP20** (BSC) | Адрес получения. Контракт `0x55d398326f99059fF775485246999027B3197955`, chain ID 56. | JSON-RPC: статус транзакции, событие Transfer на ваш адрес с точной суммой, не менее 20 подтверждений, неизменный блок. |
| **USDT TON** | Адрес получения; ключ Toncenter — желательно. | Завершённая цепочка, официальный jetton USDT, jetton-кошелёк магазина вычисляется у мастер-контракта в сети. |
| **USDT TRC20** | Адрес получения; ключ TronGrid — желательно. | Solidified-транзакция, Transfer официального контракта USDT. |
| **USDT Aptos** | Полный адрес `0x` + 64 hex. | Успешная mainnet-транзакция, Deposit в primary store получателя. |

Важно:

- **Для новых магазинов адрес BEP20 не задан** — встроенного кошелька по умолчанию нет. Укажите свой адрес в панели (или в `BSC_WALLET`), иначе USDT BEP20 будет недоступен. Магазины, которые уже принимали BEP20 в версии 1.x, сохраняют прежний адрес (см. CHANGELOG).
- Нужен только **адрес** кошелька. Приватные ключи и seed-фразы магазину не нужны и не запрашиваются.
- Публичные API Toncenter/TronGrid имеют лимиты; для регулярного потока платежей задайте API-ключи. Сбой API никогда не приводит к отказу в платеже — проверка просто повторится.
- Криптоплатежи работают только в долларовом режиме магазина (см. «Деньги и учёт»).
- Если отключены все способы пополнения, кнопка «Пополнить» в боте скрывается.

## Панель управления

Навигация сгруппирована в блоки и показывает только разделы, доступные вашей роли; на телефоне меню открывается кнопкой в шапке, таблицы превращаются в карточки. Разделы с данными обновляются раз в 30 секунд (неизменившиеся данные не передаются повторно — ETag), но никогда не перерисовываются, пока вы заполняете форму. Ошибки ввода показываются по-русски, с подсветкой нужного поля.

- **Ctrl+K** (⌘K на Mac, также `/`) — палитра команд: переход в любой раздел, поиск заказа по номеру (от 3 символов), покупателя по Telegram ID или @username, товара по названию. Результаты учитывают права сотрудника.
- **Тема**: по умолчанию как в системе; кнопка в шапке переключает светлую/тёмную, выбор запоминается в браузере.

### Вход и сессии

Basic Auth из 2.x заменён **страницей входа** (`/login`) и сессиями.

- **Первый вход** — те же `ADMIN_USER` / `ADMIN_PASSWORD` из `.env`. При каждом старте панели эта учётная запись создаётся или обновляется как **владелец**; её нельзя отключить или понизить, и пароль из `.env` для неё всегда действует.
- Сессия хранится в cookie `HttpOnly`, `SameSite=Strict` (`Secure` при HTTPS). Срок: **12 часов** без активности, не более **7 дней** с момента входа. Кнопка «Выйти» завершает сессию.
- В базе хранится только SHA-256 токена сессии; пароли сотрудников — scrypt.
- Защита от подбора: 10 неудачных входов с одного IP за 10 минут → HTTP 429 до конца окна.
- **Скрипты и мониторинг.** `PANEL_BASIC_AUTH=1` включает Basic Auth (`ADMIN_USER`/`ADMIN_PASSWORD`, права владельца) рядом с обычным входом. Изменяющие запросы (POST/PUT/DELETE) должны нести заголовок `Origin`, совпадающий с адресом панели. `GET /healthz` всегда без авторизации.

### Сотрудники и роли

Там же можно сменить роль или пароль, отключить сотрудника и завершить все его сессии. Смена роли, пароля или отключение сразу завершают сессии сотрудника. ### Кастомные эмодзи

1. **Загрузите набор**: «Товары» → «Настроить эмодзи» → вставьте ссылку `https://t.me/addemoji/Название` (нужен токен бота). Там же назначаются иконки меню, категорий и кнопок товаров. ID отдельного эмодзи бот покажет по команде `/emoji` (поле «ID кастомного эмодзи» принимает и ответ бота целиком).
2. **Вставка в текст**: поставьте курсор в названии, описании, инструкции товара или тексте рассылки и нажмите **Ctrl+E** (⌘E на Mac, также Ctrl+.) или кнопку 😊 в поле. Вкладки — наборы и «Недавние», поиск по эмодзи/ID, стрелки — выбор, Enter — вставить, Tab — следующий набор, Esc — закрыть. Вставка встаёт ровно на место курсора (выделение заменяется), Ctrl+Z отменяет.
3. **Формат**: в поле хранится токен `⟦🔥|5368324170671202286⟧` — обычный эмодзи (запасной) и ID до 20 цифр. Токен можно копировать и удалять как текст. Сервер проверяет формат, что ID есть в загруженных наборах, и не больше 50 эмодзи на поле; лимиты длины считаются по видимому тексту.
4. **В боте** токены в карточке товара становятся `<tg-emoji>`; если Telegram их отклоняет (у бота нет прав на кастомные эмодзи), карточка отправляется заново с обычными эмодзи. В кнопках, счетах, уведомлениях сотрудникам, заказах и CSV вместо токена — запасной эмодзи.

### Живая лента, CRM и «Инсайты» (3.1)

- **Колокольчик** в верхней панели — лента событий в реальном времени (Server-Sent Events, `/api/live`): оплаты, заказы на проверку, проблемные платежи, сообщения в поддержку, низкий остаток, новые покупатели, завершённые рассылки. Звук включается в самой ленте. Если поток недоступен (например, прокси буферизует ответы), панель переходит на опрос раз в 20 секунд. Для nginx добавьте для `/api/live`: `proxy_buffering off; proxy_read_timeout 1h;`.
- **Покупатели**: теги, заметка, фильтр по тегу; блокировка с причиной (только владелец). Заблокированный покупатель получает в боте короткое сообщение не чаще раза в минуту; оплаты уже созданных заказов и поддержка продолжают работать.
- **Заказы**: внутренние заметки команды в карточке заказа.
- **Товары**: флажки и панель массовых действий — показать/скрыть/удалить, сменить категорию, изменить цену на процент.
- **Поддержка**: шаблоны ответов, переменные `{name}` и `{order}`.
- **«Инсайты»** (право `analytics`): цель месяца и прогноз, воронка, тепловая карта по дням и часам, топ покупателей, когорты. Тяжёлые расчёты кэшируются на 20–60 секунд.
- **Горячие клавиши**: `?` показывает все сочетания; `G` + буква — переход в раздел; `[` — свернуть меню; `Shift+T` — тема.

### Промокоды

С версии 3.2 промокод **пополняет баланс** покупателя на фиксированную сумму; скидок при оформлении заказа больше нет.

- Код: 3–32 символа `A–Z 0–9 _ -`, регистр не важен (хранится заглавными). Сумма — от $0.01 до $10 000 (до включения USD — в Stars).
- Ограничения: общее число активаций (`0` — без лимита), активаций на покупателя (по умолчанию 1), даты начала и окончания, включён/выключен.
- Покупатель вводит код кнопкой **«🎟 Промокод»** в главном меню или в кошельке, либо командой `/promo КОД`. Ответ: «✅ Промокод активирован! На баланс зачислено $5.00. Баланс: $12.00». Понятные ошибки: код не найден, ещё не действует, истёк, лимит исчерпан, уже использован.
- Проверка лимитов и зачисление — одна транзакция: если два покупателя одновременно вводят код с последней активацией, получит её ровно один. Повторная доставка того же сообщения Telegram не зачисляет сумму второй раз.
- **Защита от подбора**: после 5 неверных попыток за 10 минут бот отвечает «Слишком много попыток, попробуй позже» — даже на правильный код. Обычный текст, не похожий на код, попыткой не считается.
- В истории кошелька начисление видно как «Промокод», в журнале — событие «Активирован промокод» (раздел «Баланс»).
- Начисления по промокодам **не выручка**: продажей считается только покупка, оплаченная с баланса. Сумма начислений — в разделе «Промокоды» и отдельной строкой «Начислено по промокодам» в Excel-отчёте аналитики (поле `promo_credits` в `/api/analytics`).

### Поддержка

- В боте: «💬 Поддержка» → **«✍️ Написать в поддержку»**; каждое следующее сообщение (текст до 3500 символов или фото с подписью) попадает в обращение. У покупателя одно открытое обращение; не больше 20 сообщений в час.
- Ответ из панели бот доставляет в тот же чат («💬 Ответ поддержки:») с кнопкой «↩️ Ответить»; при сбоях связи доставка повторяется.
- Счётчик непрочитанных — в меню панели и на обзоре.
- Ответ сотрудника — до 3500 символов, всегда одно сообщение в Telegram.

### Уведомления сотрудникам

Раздел **«Уведомления»** (владелец). Отправляет бот, поэтому он должен быть запущен; каждый получатель должен хотя бы раз написать боту.

- **Чаты**: до 20 Telegram ID. По умолчанию берутся из `ADMIN_CHAT_ID`; после первого сохранения раздела действует список из панели.
- **Виды** (каждый включается отдельно, по умолчанию все включены):

| Вид | Когда | Ограничение |
|---|---|---|
| Новый оплаченный заказ | Заказ оплачен. | — |
| Данные по ручному заказу | Покупатель прислал данные для услуги. | — |
| Сообщение в поддержку | Новое сообщение покупателя. | Одно на обращение за 10 мин |
| Мало на складе | После продажи свободный сток автотовара ≤ порога (по умолчанию 3, можно задать для отдельных товаров). | Одно на товар за 6 ч |
| Проблемный платёж | Деньги получены, но не проведены. | Одно на случай за 5 мин |
| Ошибки | Новые предупреждения и ошибки журнала. | Одно на событие за 15 мин, не больше 20 в час |
| Ежедневная сводка | Раз в день в заданное время (по умолчанию 09:00 МСК): выручка, заказы и новые покупатели за вчера и сегодня, открытые обращения, товары с малым остатком. | — |

- Сверх часовых лимитов на вид уведомления отбрасываются, а не копятся. Неотправленное повторяется с нарастающей паузой, до 10 попыток (около 4 часов); история очереди хранится 7 дней.
- Кнопка «Отправить тестовое сообщение» проверяет доставку во все чаты.

### Рассылки

- **Автоматические анонсы** (включаются отдельно): новый автоматический товар — после первой загрузки стока, ручной — при публикации; пополнение стока. Загрузки одного товара в течение 30 секунд объединяются. В сообщение попадают только название, цена и остаток.
- **Своя рассылка**: текст (необязательно — английский вариант), кнопка на каталог, товар или HTTPS-ссылку, по желанию баннер. Лимит: 3500 символов без баннера и 1024 с баннером; текст отправляется без разметки. Сначала черновик и предпросмотр, отправка — только кнопкой «Начать рассылку».
- **Аудитория (сегмент)**: все; купившие; не купившие; по языку бота (RU/EN); купившие конкретный товар; неактивные N дней (1–3650: не заходили в бот и не создавали заказов). Размер аудитории показывается до запуска. Отказавшиеся от новостей и заблокировавшие бота не учитываются.
- **Отложенный запуск**: укажите время старта (не дальше 90 дней) — рассылка получит статус «Запланирована» и начнётся сама.
- Получатели фиксируются при запуске; новые пользователи старые рассылки не получают. Рассылку можно приостановить, продолжить, отменить остаток.
- Скорость — `BROADCAST_RATE` (по умолчанию 10/с, максимум 20); рассылка идёт через общий ограничитель бота и уступает очередь ответам покупателям. Заблокировавшие бота пропускаются; при сбоях связи очередь ставится на паузу с нарастающей задержкой, а не «сгорает». Платная ускоренная рассылка Telegram не используется.
- Если связь оборвалась уже после отправки запроса, результат помечается **«неизвестный»** и не повторяется — чтобы не прислать сообщение дважды.
- Покупатель может отключить новости в «О магазине → Уведомления»; на сообщения об оплате и выдаче это не влияет.
- Отправку выполняет бот — он должен быть запущен. Записи о доставке старше 90 дней удаляются.

### Обязательная подписка на канал

В «Настройках бота» укажите `@username`, ссылку `t.me/…` или ID `-100…` (для закрытого канала нужны ID и пригласительная ссылка), добавьте бота администратором канала, нажмите «Проверить канал» и включите проверку.

- Проверяется **только новый** покупатель, один раз; подтверждение сохраняется. Существующие покупатели и те, кто пришёл при выключенной проверке, не блокируются. Смена канала не требует повторной подписки.
- Доступ дают статусы `member`, `administrator`, `creator`, а также `restricted`, если человек состоит в канале. Заявка на вступление доступ не даёт.
- Язык, поддержка, условия, уже купленное и обработка принятых оплат доступны без подписки.
- **Защита от поломки:** если проверка у Telegram не удалась 3 раза за 10 минут (например, бота убрали из админов), на 10 минут магазин пускает всех без проверки и пишет ошибку в «Ошибки». Так неверная настройка канала не закрывает магазин целиком.
- Изменения канала применяются без перезапуска.

## Как это работает для покупателя

**Первый вход.** `/start` → выбор языка (RU/EN) → при необходимости подписка на канал → главное меню: каталог, промокод, кошелёк, мои покупки, поддержка, язык, «О магазине». Язык меняется кнопкой или `/language`.

**Каталог.** Если категорий больше одной, сначала показываются категории. Товары — по 8 на странице; «Назад» возвращает на ту же страницу. В карточке — фото (если загружено), бейдж, цена (и старая цена зачёркнутой), остаток и выбор количества (−/+ или ввод числом, 1–100; для автовыдачи — не больше остатка). Порядок товаров внутри категории задаётся в панели.

**Оплата.** Кнопка «Купить» предлагает включённые способы: баланс магазина, Telegram Stars, USDT в доступных сетях.

**Промокод.** «🎟 Промокод» в главном меню или в кошельке (или `/promo КОД`) — сумма кода сразу зачисляется на баланс (см. «Промокоды»).

- При создании заказа весь нужный сток резервируется одной транзакцией на **5 минут**. Повторные нажатия используют тот же неоплаченный заказ, а не резервируют ещё. Не больше трёх неоплаченных заказов на покупателя.
- Счёт USDT за товар продлевает резерв до **15 минут** (срок счёта).
- Одобренная оплата Stars держит резерв **1 час**, потом он освобождается.
- Заказ, который уже оплачивается через Stars, нельзя параллельно оплатить с баланса или USDT — двойного списания не будет.

**Пополнение кошелька.** «Кошелёк → Пополнить», затем сумма кнопкой или своя (`12.50` или `12,50`). Команды: `/topup <Stars>` (1–10 000 Stars) и `/usdt <сумма>`.

- Stars: счёт действует 1 час, не больше 5 неоплаченных счетов в час; зачисление по курсу с округлением вниз до цента.
- USDT: от $1 до $1000, не больше трёх активных счетов, счёт действует 15 минут.

**Счёт USDT.** Одно сообщение: QR с адресом, сеть, точная сумма и кнопки копирования. К сумме добавляется уникальный «хвост» из четырёх знаков (например, `10.0012 USDT`) — по нему перевод сопоставляется со счётом. Хвост не зачисляется: 1 USDT = $1. Сумму нельзя округлять или уменьшать на комиссию. Перевод должен попасть в блок в пределах срока счёта; поздние переводы, недоплаты и чужие сети автоматически не зачисляются — нужна поддержка.

**TXID.** После перевода покупатель нажимает «Я оплатил» и присылает хеш транзакции.

- Текст считается TXID, только если похож на хеш нужной сети. Обычная переписка попытку **не тратит**.
- Проверка идёт в фоне: бот отвечает «TXID получен, проверяю…» и сам пришлёт результат.
- На счёт даётся **5 попыток**. Тратит попытку только **однозначное** несовпадение (не та сумма, адрес, сеть и т. п.). Ожидание подтверждений, индексации и недоступность API попытки не тратят — проверка повторится автоматически.
- После пятой ошибки счёт отменяется и больше не может зачислиться. Одна транзакция не может оплатить один и тот же счёт дважды, но может оплатить несколько разных счетов, если содержит несколько переводов.
- Если счёт был за товар и заказ ещё ждёт оплаты, деньги сразу списываются за заказ. Если резерв уже истёк — сумма остаётся на балансе.

**Выдача.**

- **Автовыдача**: после оплаты бот присылает все купленные позиции; длинный результат делится на несколько сообщений. Купленное можно получить снова в «Мои покупки»; там же кнопка **«🔁 Купить снова»** — тот же товар и количество, если товар ещё продаётся.
- **Ручной заказ (услуга)**: после оплаты бот показывает кнопку **«✍️ Отправить данные»**. Следующее сообщение покупателя (до 2000 символов) уходит менеджеру. Старый формат `/details <номер заказа> <данные>` тоже работает. Активные заказы со статусом видны вверху «Мои покупки». Менеджер выполняет заказ в панели («Задачи»), результат приходит покупателю в чат.

**Если что-то пошло не так.**

- Если оплату Stars не удалось сопоставить с заказом, покупатель получает сообщение, что платёж получен и поддержка разберётся, а инцидент попадает в «Ошибки → Проблемные платежи».
- Устаревшие кнопки показывают всплывающее предупреждение и не меняют экран. `/cancel` отменяет ввод.
- Доставка повторяется через 1, 2, 4… минуты (не реже раза в час) примерно сутки. Если покупатель заблокировал бота — попытки прекращаются сразу. Владелец получает одно уведомление, а не по одному в минуту.

Команды бота: `/start`, `/language`, `/promo` (активировать промокод), `/terms`, `/paysupport` (помощь с оплатой), `/cancel`; также `/wallet`, `/topup`, `/usdt`, `/details`, `/support`. Команда `/emoji` (узнать ID кастомного эмодзи) доступна только чатам из `ADMIN_CHAT_ID` (можно несколько через запятую) и из списка чатов раздела «Уведомления».

**Поддержка.** «💬 Поддержка» (или `/support`) показывает контакт из `SUPPORT_CONTACT` и кнопку **«✍️ Написать в поддержку»** — переписка идёт прямо в боте (см. «Панель управления → Поддержка»).

**Уведомления сотрудникам.** Оплаченные заказы, обращения, малый остаток, проблемные платежи, ошибки и ежедневная сводка — см. «Панель управления → Уведомления сотрудникам».

## Деньги и учёт

### Валюта

- Магазин ведёт учёт в **долларах США**, суммы хранятся целыми **центами**. Цена `2.50` в панели — это $2.50.
- Курс **Stars за $1** задаётся в «Оплата и валюта» (от 0.01 до 1 000 000). Счёт в Stars округляется **вверх** до целой звезды; зачисление пополнения Stars — **вниз** до цента. Смена курса не переоценивает цены и балансы; уже выставленные счета сохраняют свою сумму. Это внутренний курс магазина, а не рыночный.
- USDT зачисляется 1 к 1: 1 USDT = $1.
- **Перевод в доллары.** `run.py init` записывает `STARS_PER_USD=100`, поэтому новый магазин сразу работает в долларах. Старая база, где цены были в Stars, переводится один раз при старте панели или бота с `STARS_PER_USD` в `.env` (или кнопкой в «Оплата и валюта»). Перед первым переводом делается копия `<база>.before-usd-<id>.bak`; переводятся цены, себестоимость, заказы и финансовые записи. Не запускайте старую версию на переведённой базе.
- **Режим «только Stars»** (база ещё не переведена): цены — в целых Stars, доступна только оплата Stars, долларовые и криптоплатежи скрыты.

### Аналитика

Все границы дней — по **московскому времени** (Europe/Moscow).

- **Выручка** признаётся, когда оплаченный заказ **выполнен**: для автовыдачи — после выдачи, для услуги — после завершения менеджером. Пополнения кошельков и ручные изменения баланса выручкой не считаются.
- **Прибыль = выручка − возвраты − себестоимость проданного − расходы** (замены товара входят в расходы). Возврат и замена уменьшают результат в день своей записи.
- **Маржа** = прибыль / (выручка − возвраты), если знаменатель положительный.
- **Средний чек** = выручка / число заказов.
- Если хотя бы у одного заказа периода неизвестна себестоимость, прибыль и маржа показываются как «—», а известная часть себестоимости — отдельно.
- Записи «Расход / возврат» — управленческий учёт: они **не переводят деньги и не меняют баланс покупателя**. Возврат по заказу не больше его стоимости. Ошибочную запись можно отменить с причиной.
- Экспорт Excel: листы «Итоги», «По дням», «Продажи», «Расходы»; текст из товаров всегда сохраняется как текст (защита от формул). CSV также доступен.

### Себестоимость

- В карточке товара — себестоимость одной единицы. **Пустое поле — неизвестно, `0` — известная нулевая стоимость.**
- При загрузке стока можно указать себестоимость партии; иначе берётся значение из карточки. Цена фиксируется у каждой позиции; дубли её не меняют. В «Остатках» можно назначить себестоимость всему **свободному** стоку.
- При оплате в заказ записывается: для автовыдачи — сумма себестоимостей зарезервированных позиций, для услуги — себестоимость из карточки × количество. Последующие правки товара оплаченные заказы не меняют.
- Для старых заказов себестоимость не придумывается: откройте заказ из таблицы продаж и укажите **общую** себестоимость заказа с причиной — это записывается в журнал.

## Резервные копии и восстановление

### Как устроено

- Копию создаёт **панель**: автоматически каждые `BACKUP_INTERVAL_HOURS` (24 ч) и при запуске, если очередная копия просрочена; вручную — кнопкой в разделе «Резервные копии» или командой `run.py backup create`.
- Снимок берётся «на ходу» (SQLite online backup), магазин продолжает работать. В архив `.tmbak` входят база и `STOCK_KEY`; архив зашифрован отдельным **ключом восстановления**, не связанным с `.env`.
- Каждая копия **до публикации** расшифровывается и проверяется во временной папке: целостность SQLite, внешние ключи, балансы, покупки, контрольные суммы стока, расшифровка всех секретов. Результат проверки запоминается, поэтому скачивание не расшифровывает архив заново; кнопка «Проверить восстановление» всегда делает полную проверку.
- **Хранение**: остаются `BACKUP_KEEP` (14) последних проверенных копий, более старые удаляются. Самая свежая проверенная копия не удаляется никогда; непроверенные более новые не трогаются.
- Перед созданием проверяется свободное место (примерно 3 × размер базы + 16 МиБ). Максимальный размер снимка — 256 МиБ.
- Файлы по умолчанию: `data/backups/*.tmbak` и `data/backup-recovery.key`. На Unix создаются с правами 0600.
- `BOT_TOKEN` и `ADMIN_PASSWORD` в архив **не входят** — храните их отдельно.
- **Фото товаров** (`data/product-images/`) входят в архив (формат 2: до 8 МиБ на файл, 64 МиБ всего), проверяются по контрольным суммам и восстанавливаются в `data/product-images` новой папки. Архивы прежнего формата по-прежнему восстанавливаются. Учётные записи сотрудников, промокоды, обращения и настройки уведомлений хранятся в базе и входят в копию.

### Что сделать один раз

В панели скачайте **копию** и **ключ восстановления** и сохраните их **вне сервера магазина и отдельно друг от друга**. Копия на том же диске не спасёт при потере сервера; автоматической выгрузки во внешнее хранилище нет. Потерянный ключ заново не создаётся, если архивы уже есть.

### Команды

```bash
python run.py backup create
python run.py backup verify themarket-20261104T120000Z-1234abcd.tmbak --key /secure/themarket-recovery.key
python run.py backup restore themarket-20261104T120000Z-1234abcd.tmbak --key /secure/themarket-recovery.key --output /srv/themarket-restored
```

`verify` и `restore` не зависят от текущего `.env` и `STOCK_KEY`. В Docker: `docker compose exec panel python run.py backup create`.

### Восстановление по шагам

1. **Остановите бота и панель.**
2. Сохраните текущую папку `data/` (на случай, если понадобится вернуться).
3. Выполните `backup restore` в **новую** папку — существующую команда не перезапишет. Результат:
   - `<папка>/data/shop.sqlite3` — база;
   - `<папка>/recovered.env` — `STOCK_KEY` и `DATABASE_PATH` этой базы. Это секретный файл.
4. Подключите восстановленную базу: укажите `DATABASE_PATH` на неё (или поставьте её на место старой, удалив рядом старые файлы `-wal` и `-shm`) и перенесите `STOCK_KEY` из `recovered.env` в `.env`. `BOT_TOKEN` и `ADMIN_PASSWORD` задайте как прежде.
5. Запустите **только панель**. Отмените устаревшие рассылки (в снимке могут быть рассылки, уже отправленные после его создания). Сверьте платежи и выдачи за время между снимком и сбоем: балансы, оплаты и статусы доставки вернулись к моменту копии.
6. Запустите бота.

При переносе на новый сервер задайте `BACKUP_DIRECTORY` и `BACKUP_RECOVERY_KEY_PATH`, если храните архивы и ключ не в путях по умолчанию.

## Безопасность

- **`STOCK_KEY`** шифрует сток. Без него купленные и непроданные товары не расшифровать. Не меняйте его у существующей базы, храните копию `.env` в надёжном месте, не коммитьте и не пересылайте. Хеши для поиска дублей стока считаются через HMAC на этом же ключе.
- **Что зашифровано (Fernet, `STOCK_KEY`)**: сток, данные ручных заказов, выданные результаты, очередь доставки, сообщения поддержки, очередь уведомлений сотрудникам, API-ключи Toncenter/TronGrid, тексты рассылок, пригласительная ссылка канала. Резервные копии — отдельным ключом восстановления.
- **`.env`** записывается атомарно с правами 0600; при запуске права исправляются, если файл доступен другим. Папки логов и данных в Docker — 0700. На Windows действуют права папки пользователя.
- **Панель — только через HTTPS.** Вход — страница входа и сессионная cookie (`HttpOnly`, `SameSite=Strict`, `Secure` при HTTPS); по умолчанию панель слушает только `127.0.0.1`. Для удалённого доступа — reverse proxy с TLS (см. «Docker»). Basic Auth выключен, пока не задан `PANEL_BASIC_AUTH=1`.
- **Сотрудники**: у каждого свой логин и роль с минимально нужными правами (см. «Сотрудники и роли»); пароли — scrypt, в базе хранятся только хеши паролей и токенов сессий. Не передавайте пароль владельца — заведите сотруднику свою учётную запись.
- **Защита от подбора**: 10 неудачных входов с одного IP за 10 минут → блокировка (HTTP 429) до конца окна.
- **Прочее**: проверка `Origin`/`Host` для изменяющих запросов, лимит тела запроса (1 МБ, загрузка стока — 6 МБ) до разбора данных, CSP и заголовки безопасности на всех ответах, `Cache-Control: no-store`. Скачивание копий и ключа восстановления — только POST-запросом из панели.
- **Логи**: токен бота, пароль панели и `STOCK_KEY` вырезаются из логов и журнала (`[скрыто]`). Содержимое выдачи и пароли товаров в журнал не пишутся.
- Не загружайте реальный сток, базу или `.env` в Git и публичные хранилища (`.gitignore` и `.dockerignore` их уже исключают).

### Обновление и миграции

1. Сделайте резервную копию (`run.py backup create` или кнопкой в панели).
2. Остановите бота и панель, замените файлы магазина (папки `data/` и `.env` не трогайте).
3. Запустите снова. На Windows окно запуска само доустановит изменившиеся библиотеки.
4. Обновите страницу панели с **Ctrl+F5**.

Схема базы обновляется **автоматически** при запуске (версия хранится в `PRAGMA user_version`); миграции идемпотентны, покупки, балансы и сток сохраняются. Текущая версия схемы — 4 (TheMarket 3.0). Переход с 2.x описан в [CHANGELOG.md](CHANGELOG.md).

### Журнал и рост базы

Бот и панель периодически убирают служебные данные: записи доставки рассылок старше 90 дней, отправленные уведомления старше 7 дней, информационные записи журнала (заказы, товары, настройки, система) старше `AUDIT_RETENTION_DAYS` (180 дней). Уборка идёт маленькими порциями и не блокирует магазин. Предупреждения, ошибки и все записи о деньгах (платежи, балансы, финансы) не удаляются никогда.

| «Панель завершилась при запуске» / «Панель не ответила за 2 минуты» | Причина — в «Журнале запуска» или `data/logs/panel.log`. |
| «Нет свободного порта для панели» | Заняты порты от `PORT` до `PORT+19`. Освободите порт или задайте другой `PORT`. |
| «В файле .env нет пароля панели или ключа стока…» | Закройте и снова откройте окно запуска — недостающий пароль будет создан. Если пропал `STOCK_KEY` — верните его из копии `.env` или резервной копии. |
| «Уже запущен другой экземпляр…» при открытии окна | Окно запуска уже открыто — найдите его. |
| `Python 3.12 or newer is required` (START.cmd) | Установите Python 3.12+ с python.org с tcl/tk и py launcher. |
| Панель за прокси: при сохранении «Недопустимый источник запроса» (403) | Добавьте `proxy_set_header Host $host` или задайте `PANEL_ORIGIN`. |
| Панель после обновления открывает страницу входа | Так и должно быть в 3.0: войдите с `ADMIN_USER`/`ADMIN_PASSWORD`. Скрипты с Basic Auth — задайте `PANEL_BASIC_AUTH=1`. |
| «Недостаточно прав для этого действия» (403) | Раздел или действие недоступно роли сотрудника — права меняет владелец в «Сотрудниках». |
| Не приходят уведомления сотрудникам | Бот должен быть запущен; каждый получатель хотя бы раз написал боту; проверьте чаты и включённые виды в «Уведомлениях» и нажмите «Отправить тестовое сообщение». |
| Панель отвечает 429 | 10 неверных паролей за 10 минут с этого IP — подождите. За прокси проверьте `FORWARDED_ALLOW_IPS`, иначе все клиенты выглядят как один IP. |
| `Недостаточно места на диске для резервной копии…` | Освободите место или уменьшите `BACKUP_KEEP`. |
| `Backup operation failed. Check archive, recovery key, paths and permissions.` | Проверьте путь к архиву, что ключ подходит к нему и что папка `--output` ещё не существует. |
| USDT BEP20 нет в боте | Не задан адрес получения: укажите его в «Оплата и валюта». |

## Производительность и масштаб

Магазин рассчитан на **тысячи покупателей, сотни заказов в день и 100 000+ заказов** в базе на одном обычном сервере (VPS с 1–2 ядрами и SSD).

### Как устроено

- Обновления Telegram обрабатываются параллельно (сообщения одного покупателя — по порядку), тяжёлая работа (QR-коды, запросы к базе в горячих местах) вынесена из цикла событий.
- **Общий ограничитель исходящих сообщений**: `TELEGRAM_RATE` (25/с) на весь бот и не чаще 1 сообщения в секунду в один чат (кратковременно до 3). Ответы покупателям идут первыми, затем служебные сообщения (выдача, поддержка, уведомления), затем рассылки. Если Telegram отвечает «слишком много запросов» (RetryAfter), отправка приостанавливается целиком на указанное время.
- Панель не отдаёт неограниченных списков: заказы, покупатели, журнал, сток, промокоды и обращения — постранично с поиском на сервере; опрос состояния — маленький ответ со счётчиками и ETag.

### Замеры

Нагрузочный тест бота (`loadtest_bot.py`): 2000 покупателей, 16 000 обновлений (каталог, карточки, оформление, оплата с баланса, счета, покупки, поиск, поддержка), имитация Telegram с задержкой 50 мс.

| Показатель | Результат | Цель |
|---|---|---|
| Пропускная способность (без ограничителя) | **438 обновлений/с** | ≥ 200 |
| Собственное время обработки, p95 (без задержки Telegram) | **37 мс** | < 300 мс |
| Максимальная задержка цикла событий | **72 мс** | < 100 мс |
| С ограничителем как у Telegram (`--rate 25`) | **~200 обновлений/с** | — |

Нагрузочный тест базы (`loadtest_db.py`): 300 товаров, 50 000 единиц стока, 20 000 покупателей, 150 000 заказов, 300 000 записей кошельков, 500 000 записей журнала (медиана повторных вызовов).

| Операция | Время |
|---|---|
| Все вызовы бота (товар, каталог, категории, поиск, заказ, оплата, кошелёк, покупки) | **< 5 мс** каждый |
| Панель: состояние (`/api/state`) | 37 мс |
| Панель: обзор (дашборд) | 18 мс |
| Панель: страница заказов | 4 мс |
| Панель: страница покупателей | 3.5 мс |
| Панель: аналитика за месяц | 12 мс |
| Панель: текстовый поиск по журналу | 132 мс |

### Как запустить замеры

```bash
python loadtest_db.py                              # создаёт базу во временной папке и замеряет (несколько минут)
python loadtest_db.py --db big.sqlite3 --keep      # сохранить сгенерированную базу и переиспользовать её
python loadtest_db.py --json                       # результат в JSON
python loadtest_bot.py                             # 2000 покупателей × 8 обновлений, задержка Telegram 50 мс
python loadtest_bot.py --rate 25                   # с рабочим ограничителем исходящих сообщений
python loadtest_bot.py --users 5000 --latency 0.1 --profile   # своя нагрузка + профиль самых затратных функций
```

Оба скрипта работают на временных данных, не трогают `data/` и не обращаются к Telegram. Нужны библиотеки из `requirements.txt`.

### Лимиты Telegram

- Telegram пропускает около **30 сообщений в секунду** на бота в целом и около 1 в секунду в один чат. Поэтому `TELEGRAM_RATE` по умолчанию 25 — с запасом; поднимать его выше 30 бессмысленно (Telegram начнёт отвечать RetryAfter).
- Рассылки по умолчанию идут со скоростью **10 сообщений/с** (`BROADCAST_RATE`, максимум 20), чтобы оставлять место ответам покупателям: рассылка на 10 000 человек занимает около 17 минут.
- При пиковой нагрузке узким местом становится лимит Telegram на исходящие сообщения, а не сервер: по замеру выше бот с рабочим ограничителем обслуживает около 200 обновлений в секунду.

### Когда нужен сервер мощнее

- Цикл событий бота регулярно задерживается больше 100 мс или ответы бота заметно запаздывают при свободном лимите Telegram (смотрите `data/logs/bot.log`).
- База выросла до нескольких гигабайт (сотни тысяч заказов и миллионы записей журнала) и разделы панели открываются дольше секунды; снимок базы больше 256 МиБ не поместится в резервную копию.
- Медленный диск (HDD, перегруженный общий хостинг): SQLite чувствителен к задержкам записи — выбирайте SSD/NVMe.

Сначала прогоните `loadtest_db.py` и `loadtest_bot.py` на целевом сервере: если цели выполняются, ресурсов достаточно. Горизонтального масштабирования нет (один процесс бота на базу).

## Ограничения

- **Три фиксированные роли** (владелец, менеджер, поддержка); свои наборы прав не настраиваются.
- **Один процесс бота на базу** и один сервер: SQLite, без горизонтального масштабирования.
- **TON**: вычисление jetton-кошелька в сети проверено только на имитации API. Прежде чем полагаться на TON, проведите **один реальный тестовый платёж**.
- **Возвраты Stars не автоматизированы.** Проблемные платежи разбираются вручную через «Ошибки → Проблемные платежи» и поддержку.
- Крипто-платёж проверяется только по присланному TXID — входящие переводы не сканируются. Поздние переводы, недоплаты и переводы не в той сети требуют ручного разбора.
- Сообщение, отправленное в момент сбоя связи, может быть доставлено повторно (для выдачи) или помечено «неизвестный результат» (для рассылок). Новая единица стока при повторе не тратится.
- Резервные копии хранятся локально; выгрузку во внешнее хранилище нужно организовать самостоятельно. Снимок базы — не больше 256 МиБ. Фото товаров в копию не входят.
- Аналитика — управленческая, по введённым данным; часовой пояс отчётов — только Москва. Комиссии, налоги и курсовые разницы автоматически не учитываются.
- Панель — только на русском; бот — на русском и английском (тексты товаров и условий не переводятся).
- Реальные платежи и выдачу стоит проверить на тестовом боте перед запуском: автоматические тесты не заменяют такую проверку.
